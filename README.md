# nura-basic-terminal

<p align="center">
  <img src="screenshots/firefox-nuraos.png" width="540" alt="Firefox on the NuraOS site, running fullscreen via `app` — the status bar shows the SMS and missed-call indicators next to the signal strength">
</p>

Make a postmarketOS phone usable **without a GUI** — and give it one when
you want it (`app firefox`, above). If your phone runs a bare
VT console (fbcon) — as a hotspot, a server, a mini-terminal — the hardware
buttons do nothing, the console font is unreadably small, there's no way
to see battery or signal without logging in, and no way to scroll back
through what you typed.

This repo fixes all of that:

| Piece | What it does |
|---|---|
| `phone-screen-toggle` | Power button turns the screen off and back on; double click toggles the onscreen keyboard — without logging out |
| `phone-font` | Volume up/down steps the console font through 16 → 48 px |
| `phone-statusbar` | A status bar painted over the top of the framebuffer: cellular tech + signal (left), battery + clock (right) — and the same line inside graphical sessions (`--text` mode feeds sway's bar) |
| `phone-gestures` | Touchscreen gestures on the console: drag = scroll through tmux scrollback, double tap = TAB (inside the tmux session only) |
| `phone-brightness` | Backlight follows the ambient light sensor: dim in the dark, bright in the sun |
| `phone-ir` | Send IR commands with the phone's IR LED: NEC / Samsung / Sony / RC5 / raw timings, or named codes from a config file |
| `sms-send` / `call` | Send an SMS, and dial / answer / hang up calls, from the command line |
| `sms-handler` | Runs a command for every received SMS — forward it, upload it, archive it — configured in `/etc/phone-sms-handler.conf`; the modem inbox doubles as the retry queue |
| `call-watcher` | Rings on incoming calls, lights the screen, shows RING/CALL in the status bar; volume-up answers, volume-down silences the ringer |
| `notify-led` | The notification LED: fast blink while a call rings, steady while active, slow blink for a missed call, double blink for an unread SMS, steady while charging (`notify-clear` dismisses) |
| `ter-148n.psf.gz` | A 24×48 console font (3× pixel-scaled Terminus), regenerated by `scale-psf.py` |
| `phone-buttons.toml` | hkdm hotkey config binding the buttons to the scripts |
| `app` | Run any Wayland app fullscreen: a sway kiosk at 3× scale with the `wvkbd` on-screen keyboard (power double-click toggles it, vol-up + power screenshots to `~/Pictures`), the status bar kept on top |

Tested on a Xiaomi Mi A2 Lite (*daisy*, msm8953) running postmarketOS v26.06,
1080×2280 screen. Everything is plain shell + Python against sysfs and
`/dev/fb0`, so it should port easily to other devices — see
**Customizing** below.

## Requirements

- postmarketOS (or any Linux with an fbcon VT console and systemd)
- `hkdm` — hotkey daemon (`apk add hkdm`)
- `terminus-fonts` — provides `ter-116n`…`ter-132n` (`/usr/share/consolefonts`)
- `python3` — for the status bar and the gesture daemon
- `tmux` — provides the console scrollback the gestures drive
  (`apk add tmux`)
- for `phone-ir`: a C compiler and the kernel UAPI headers
  (`apk add build-base linux-headers`) — `irsend` is built on the device
- for the telephony tools: `modemmanager` (running), `polkit`, and
  `pulseaudio` + `pulseaudio-utils` (`paplay` for the ring tone) — on
  postmarketOS these are all in the base install
- optional: `buffyboard` (onscreen keyboard) and `ttyescape` (hold
  vol-down + tap power 3× to switch to another VT). The keyboard toggle
  needs a buffyboard that resizes the console around the keyboard;
  upstream ≥ 3.6.0 does this via KDFONTOP, which is broken on some
  kernels (ENOSPC for fonts > 32 px) — this device runs a patched build
  that probes the max row count with `TIOCSWINSZ` instead.
- for `app`: `sway`, `wvkbd`, `seatd` (provides `seatd-launch`) and `grim`
  — `install-graphical.sh` runs `apk add` for all of them

## Install

Copy this directory to the phone (e.g. `scp -r . phone:/tmp/basic-terminal`),
then on the phone as a sudoer:

```sh
doas sh /tmp/basic-terminal/install.sh            # everything
```

Or install one piece at a time: `install-buttons.sh` (buttons + fonts),
`install-statusbar.sh`, `install-gestures.sh`, `install-brightness.sh`,
`install-ir.sh`, `install-telephony.sh`, `install-graphical.sh`.

What the installers do:

- `install.sh` — meta-installer; runs every component installer below
  in order.
- `install-buttons.sh` — installs the font + `phone-screen-toggle` + `phone-font`,
  drops `phone-buttons.toml` into `/etc/hkdm/config.d/`, sets the boot font
  via `FONT=` in `/etc/vconsole.conf` (and `/etc/conf.d/ttyescape.conf` so
  the escape VT matches), restarts hkdm.
- `install-statusbar.sh` — installs `phone-statusbar` + its systemd unit
  (enabled at boot), the `/etc/profile.d` `clear` shim, and pads `/etc/issue`
  with two blank lines so the login prompt starts below the bar. Installs
  `/etc/phone-statusbar.conf` (battery tunables) only when none exists.
- `install-gestures.sh` — installs `phone-gestures` + its systemd unit
  (enabled at boot) and the `/etc/profile.d` hook that wraps tty1 logins
  in tmux, and drops a `~/.tmux.conf` (status line off, 5000 lines of
  history) where none exists. Takes effect at the next tty1 login.

All the installers source `backup-helper.sh`. When one overwrites a file
**that actually changed**, the old version is copied, timestamped, into
`<device home>/backup` (e.g. `/home/<device user>/backup/phone-gestures.20261103-115600`),
so a bad deploy can be rolled back by hand. Reinstalling an identical file
backs up nothing, and only the 2 newest copies of each file are kept — these
scripts are reinstalled often and the folder shouldn't grow without bound.
Tune with `BACKUP_KEEP=` (how many to keep) and `BACKUP_DIR=` (where).
Hand-edits made directly on the device should land there too.

`backup <installed> [incoming]` — with `incoming` it skips identical files;
with one argument the backup is unconditional, for files edited in place
(`/etc/vconsole.conf`, `/etc/conf.d/ttyescape.conf`), where the caller first
checks whether the edit would change anything. `install-ir.sh` compiles
`irsend` to a temp file before installing it, so there is something to
compare against — and so a failed `cc` can't leave a truncated binary in
`/usr/local/bin`.
- `install-brightness.sh` — installs `phone-brightness` + its systemd
  unit (enabled at boot) and `/etc/phone-brightness.conf` (when none
  exists). `phone-screen-toggle` pokes it awake on screen-on.
- `install-ir.sh` — compiles `irsend` into `/usr/local/bin`, installs
  `phone-ir`, and drops an example `/etc/phone-ir/remotes.conf` (only when
  none exists, so your own codes are never overwritten).
- `install-telephony.sh` — installs the polkit rule (voice access for the
  device user), adds its own hkdm binding for the volume buttons
  (`phone-volume`; the buttons install's bindings are left alone),
  updates `phone-statusbar` (RING/CALL indicator), puts `call`,
  `sms-send`, the `call-watcher` user service + ring tone, and the
  `sms-handler` user service in the device user's `~/.local`, and drops
  `/etc/phone-sms.conf` (SMSC) and `/etc/phone-sms-handler.conf`
  (received-SMS command) only when none exists. Enables and (re)starts
  everything it touched.
- `install-graphical.sh` — installs `app`, `app-inner`, `swaybar-user`
  and `phone-screenshot` into `/usr/local/bin`, `/etc/app-sway.conf`, and
  the `phone-screenshot.toml` hkdm binding; also the doas rule
  (`49-app-doas.conf`, from a `@USER@` template like the polkit one) that
  lets the device user run `app` as root without a password, plus the
  `/etc/profile.d/app-alias.sh` alias so a plain `app` works in login
  shells; `apk add`s sway / wvkbd /
  seatd-launch / grim and restarts hkdm. Needs the buttons and statusbar
  components (`phone-screen-toggle` carries the session-aware patches,
  the bar's `status_command` is `phone-statusbar --text`).

## How it works

**Power button** (`phone-screen-toggle`): single click toggles the screen —
off = backlight 0 + `setterm --blank force` (the logged-in session on tty1
is untouched); on = `setterm --blank poke` + restore the saved brightness,
then `SIGUSR1` nudges so the status bar repaints and buffyboard redraws the
keyboard. A **double click** (releases < 450 ms apart) toggles the onscreen
keyboard instead: on the console that's buffyboard (stopping it lets the
console grow back to full height, starting it shrinks the terminal rows to
the space above the keyboard); inside a graphical session it's wvkbd (see
below). **Vol-up held + power click** takes a screenshot (grim, saved to
the device user's `~/Pictures`). The `ttyescape` combo (vol-down held +
power taps) is preserved: the script bails out if `/tmp/ttyescape.tmp`
exists, and `phone-font` ignores volume presses within 2 s of a power
press — in either direction, so neither combo bumps the font.

**Font ladder** (`phone-font`): steps between the stock Terminus sizes
(16/20/24/28/32 px) plus a generated 48 px one; the current step lives in
`/run/phone-buttons/font-index` (volatile — resets to the biggest after a
reboot, which is usually what you want on a phone). It stands down while
a call is ringing or active, so the telephony volume buttons own the keys
then — each component binds the keys in its own hkdm config, and hkdm
runs every matching binding.

**Big font** (`fonts/scale-psf.py`): Terminus tops out at 32 px, so
`fonts/ter-148n.psf.gz` is ter-116n scaled 3× to 24×48. Regenerate with
`python3 fonts/scale-psf.py /usr/share/consolefonts/ter-116n.psf.gz fonts/ter-148n.psf.gz 3`.
`python3 fonts/test-scale-psf.py` self-checks that pipeline: it scales a tiny
PSF1 font and loads the result with the status bar's own font loader,
asserting the unicode table and the scaled pixels.
Gotchas handled: PSF1 unicode tables are little-endian u16 with 0xFFFF
terminators / 0xFFFE sequence separators and contain UTF-16 surrogate
pairs; PSF2 wants UTF-8 values with 0xFF/0xFE markers.

**Status bar** (`phone-statusbar`): a Python daemon that paints only the
top 96 px band of `/dev/fb0` — the notch zone, useless for text anyway —
once per minute, just after the wall-clock minute flips, and immediately
when the screen turns on: `phone-screen-toggle` sends it `SIGUSR1`, which
interrupts its sleep. While the screen is dark the daemon blocks on its
wake pipe (the backlight's single writer is `phone-screen-toggle`, which
pokes it on wake), so it costs nothing. The terminal below is never
redrawn; text that scrolls under the bar is healed by the next repaint.
The bar is a **fixed** height with its own fixed 24×48 font, so it never
moves when you change the console font. Values (battery from
`/sys/class/power_supply/*/capacity|status`, cellular from `mmcli -m any`,
clock from `strftime`) are fetched only once per repaint — so the clock
lags at most one repaint behind. Unread notifications (the same flags
`notify-led` blinks for) appear right of the signal strength — `SMS`,
`MISS`, in green — but are hidden while a call rings or is active, where
RING/CALL already fills the bar. The battery's Charging status is
confirmed against `current_now` (the fuel gauge's status word
misreports on this port), and a full battery is a plain `100%`.

A failed modem query (ModemManager not
up yet at boot) is not cached: it retries at the next repaint, so the
bar recovers within a minute instead of showing NO NET for the whole
`MODEM_EVERY` window. The same script has a `--text` mode for graphical
sessions (see **Graphical apps**): instead of painting the framebuffer it
prints the identical status line for sway's bar, with the same battery
discipline — one wake per minute and none while the screen is dark;
call-watcher pokes it with SIGUSR1 on every call transition, since the
systemd service it would signal is stopped while a session runs.

**Gestures** (`phone-gestures`): fbcon has no scrollback, so tty1 logins
are wrapped in tmux (a `/etc/profile.d` hook execs `tmux new-session -A -s
phone`; ssh and other VTs are untouched) and a root daemon reads the
touchscreen's evdev device directly. Vertical drags in the terminal area —
everything above the on-screen keyboard while it's shown, the whole screen
when it's not — scroll the tmux session through copy mode, "natural"
direction (content follows the finger): drag down = older, drag up =
newer, quick flick down = 20-line jump, and reaching the live bottom
leaves copy mode. A **double tap** in the terminal area injects a TAB
through a one-key uinput keyboard, the same mechanism buffyboard uses to
type — but only while the tmux session is running. An injected TAB goes to
whatever owns tty1, and at a login prompt that is agetty, which rejects the
entire login name on any control character (`invalid character 0x9 in login
name`) and exits; gating TAB on `tmux has-session` keeps it off the login
prompt, the same way the scroll gestures already no-op without a session.
The daemon coexists with buffyboard: libinput doesn't grab the device, so
both read the same events. `synthtouch.c` builds a synthetic protocol-B
touchscreen via uinput for testing the whole chain without touching the
real screen.

Gotcha handled: the Goodix driver advertises an ABS range of 0–4095 in its
`EVIOCGABS` info but reports coordinates that are **already screen pixels**
(0–2279), so touch positions must be used as-is, never rescaled against the
advertised maximum. Rescaling shrank every touch by ~0.56 and put taps on
the on-screen keyboard (y ≥ 1520) inside the terminal zone at y ≈ 850–1270:
typing two letters quickly read as a double tap and fired a TAB, which made
console logins impossible. To re-verify after a driver change, compare a
touch's reported y against the buffyboard key it activates — the keyboard's
five rows start at y = 1520 and are 152 px tall.

**Adaptive backlight** (`phone-brightness`): a daemon that reads the
ambient light sensor (any IIO device with `in_illuminance_input`; an
LTR-F216A on this phone) every `POLL_EVERY` seconds while the screen is
on, and sets the backlight on a logarithmic lux→brightness curve —
perception is logarithmic, so equal light ratios give equal brightness
ratios. `MIN_BRIGHTNESS` in a dark room, `MAX_BRIGHTNESS` at
`LUX_MAX` ambient light. Readings are smoothed with an exponential
moving average and a 12% deadband so the backlight doesn't hunt around
a threshold. While the screen is off (backlight 0) it blocks on its
wake pipe — the backlight's single writer, `phone-screen-toggle`,
SIGUSR1s it when the screen comes back, and it re-samples then. Manual
`echo N > .../brightness` changes are adopted as the baseline but
overridden at the next adjustment; stop the service to hold a level.

**IR blaster** (`phone-ir`, `irsend`): on this phone the IR LED hangs off
SPI6's MOSI line (GPIO 20) — Xiaomi's Android kernel drives it through a
`peel_ir` SPI driver that mainline lacks, and the postmarketOS device tree
has no node for it. `phone-ir` frees the pins by unbinding the `spi_qup`
controller (`7af6000.spi`), runs `irsend` — a small real-time C program that
bit-bangs the carrier (default 38 kHz, 33 % duty; measures within 0.1 % of
the request, `irsend -v` prints it) from a list of mark/space microseconds —
and always rebinds the controller afterwards. The LED supply (regulator l8)
is already on because the SD slot shares it. The phone can **send only**: no
receive path was found (the MISO line never moves), so codes have to come
from elsewhere, e.g. the Flipper-IRDB.

```sh
doas phone-ir test                    # 5 s of bursts: aim a phone camera at the top edge
doas phone-ir nec 0x04 0x08 [N]       # NEC address/command, N repeat codes
doas phone-ir raw 9000 4500 560 ...   # raw mark/space timings, µs
doas phone-ir -f 36000 raw ...        # other carrier frequency
doas phone-ir send NAME [N]           # a named code from /etc/phone-ir/remotes.conf
phone-ir list
```

Built-in encoders: NEC, NEC with 16-bit address, Samsung32, Sony SIRC (12-bit,
40 kHz), Philips RC5 (36 kHz, toggle bit flips on every press). Anything else
goes in as `raw`.

**Telephony** (`call`, `sms-send`, `call-watcher`, `phone-volume`): voice
calls and SMS through ModemManager's D-Bus API — no ofono, no GUI dialer.
`call <number>` creates and starts an MM call object; `call` lists them,
`call answer [n]` accepts, `call hangup [n]` ends. `sms-send <number>
<text>` creates an SMS, sends it and deletes the object; the modem here
has no default SMSC stored, so the message center comes from
`/etc/phone-sms.conf` (see Customizing). Incoming calls are handled by `call-watcher`, a user
service that watches MM's call signals: on a ring it plays
`~/.local/share/ring.wav` in a loop, lights the screen via
`phone-screen-toggle --do-toggle` (only when the screen-off flag exists,
so it never darkens an already-lit screen), and writes
`ringing <number>` to `/tmp/phone-call-state`; `phone-statusbar` reads
that file and shows a green `RING` (or `CALL`) on the left, poked awake
with SIGUSR1 on every transition so it appears the moment the phone
rings. Terminated call objects are deleted so the list stays clean.
While the call rings, `call-watcher` also arms the call audio routing
(see below), or the call would connect silent.
The volume buttons go through `phone-volume` while a call rings:
**volume-up answers, volume-down silences the ringer** (a flag file the
ring loop checks — the call itself keeps ringing, and volume-up still
answers it); during a call they step the earpiece volume (`RX1
Digital`, ±8 dB per press). Outside a call the buttons belong to the
buttons install again — telephony ships its **own** hkdm config
(`telephony/phone-telephony.toml`) for the volume keys, and `phone-font`
stands down while a call is up, so either component works without the
other. Voice control over MM needs a polkit rule
(`49-modem-voice.rules.in`, with the device user substituted by the
installer → `/etc/polkit-1/rules.d/`) — messaging is allowed by distro
defaults, voice is not.

**Received SMS** (`sms-handler`, a user service): every SMS the modem
receives is written as JSON to a volatile copy under `/tmp/sms/` (named
uniquely by content, so the network redelivering the same message after
an outage collapses to one file) and handed to the `COMMAND` configured
in `/etc/phone-sms-handler.conf` — a shell line run with `SMS_NUMBER`,
`SMS_TEXT`, `SMS_TIMESTAMP` and `SMS_FILE` in its environment, re-read
before every scan so edits apply without a restart. Forwarding to
another phone is the documented example in that file (`sms-send` with
`$SMS_NUMBER`/`$SMS_TEXT`). Exit 0 means handled and the SMS is deleted
from modem storage; anything else leaves it in the modem inbox, which
doubles as the retry queue — a failing command delays a message instead
of losing it, and nothing is stored on the phone across reboots.

**Call audio routing**: the voice call itself never passes through
Linux (q6voiced just opens the hostless VoiceMMode1 PCM, and the DSP
routes the audio), so a call is only audible along paths connected when
the session starts. `call-watcher` therefore sets, while the call still
rings: the mic uplink route + gains (`ADC1`/`TX1` — stock levels are far
too quiet), and the earpiece downlink — the voice mixer plus the
codec-internal route from the UCM `EarpieceEnableSeq`, which nothing
applies during a call (PulseAudio's UCM verb would own the mixers, but
it tears them down when its sinks suspend). The earpiece codec route is
released again when the call ends. Known limitation: the **loudspeaker**
(QUIN MI2S backend) stays silent during calls even with its voice mixer
enabled — the fix for that lives in the DSP route setup, not userspace.

```sh
call +15551234567       # dial
call                    # list: 0: incoming ringing-in /org/.../Call/8
call answer             # answer the ringing call
call hangup             # end all ongoing calls
sms-send +15551234567 "on my way"
echo "running late" | sms-send +15551234567
```

**Notification LED** (`notify-led`): a user service that watches
ModemManager itself (no dependency on the telephony component) and blinks
the white indicator LED: fast blink while a call rings, steady while a
call is active, slow blink after a **missed call** (an incoming call that
ended unanswered — detected even when `call-watcher` deletes the call
object first, via the CallDeleted signal) and a double blink for a
**received SMS**, until `notify-clear` dismisses them — alone it clears
both, `notify-clear sms` / `notify-clear missed` just one, so an unread
SMS can be marked seen without dropping the missed-call indication. The
flags are
files in `~/.local/state/notify-led/`, so they survive restarts and
reboots. daisy's LED is a single white diode (one channel of its aw2013
driver), so the patterns are brightness-only; the daemon writes
`/sys/class/leds/white:indicator/brightness` directly, made
user-writable by a udev rule. If both a missed call and an SMS are
pending, the missed call wins. A charging battery also shows a steady
light, at the lowest priority — checked against `current_now`, because
the pmi8994 fuel gauge's status word claims Charging while the battery
is discharging; the current's sign is the truth.

**Graphical apps** (`app`): `app firefox` (or any Wayland app) runs a
sway kiosk on VT3 — `openvt` gives sway the VT, `seatd-launch` gives it a
seat outside a logind session, and the app itself runs as the device user
against the root-owned wayland socket. The launcher runs as root (it
pauses console services and switches VTs); the doas rule installed with
it lets the device user type just `app`, no password. The output is scaled 3× (1080×2280
physical → 360×760 logical), so buttons and page content are finger-sized;
the screenshot at the top of this README was taken that way. The console
stack (buffyboard, status bar, gestures) is paused while the session runs
and restored when the app exits — sway exits with it, like cage did. The
on-screen keyboard is `wvkbd`, started hidden: buffyboard renders on fbcon,
which a Wayland compositor doesn't display, so it can't come along — but
the power double-click toggles wvkbd inside the session (wvkbd's signals
are one-way, so visibility is tracked in `/run/phone-buttons/wvkbd-shown`),
and it's colored to match buffyboard's default breezy-light theme so the
two keyboards look the same. Screenshots are `grim`, fired by the
vol-up + power combo (or `phone-screenshot` directly), saved to
`~/Pictures/screenshot-<timestamp>.png`.

The status bar comes along too: sway's own bar runs across the top (32
logical px, like the fbcon one; the window title bar is off —
`default_border none`), fed by `phone-statusbar --text` as its
`status_command`. The line is padded to fill the bar width, so the
cellular half sits at the left edge and battery/clock at the right,
clear of the notch — swaybar right-aligns an unpadded line. Sway spawns
its bar as root, and root's swaybar can't work here — with the user
session bus present its tray code segfaults, without a bus it exits —
so `swaybar_command` points at `swaybar-user`, which opens the
root-owned sway sockets, drops to the device user and runs the real
swaybar from there. A ring still shows immediately: call-watcher
SIGUSR1s the `--text` instance directly.

## Customizing

All the device-specific paths are constants at the top of the scripts:

- `phone-screen-toggle`: `BL=` (backlight sysfs dir), `DOUBLECLICK_CS`
- `phone-statusbar`: `FB`, `SYSFB`, `BACKLIGHT`, `BATTERY`, `BAR_FONT`,
  `BAR_H` (px), `EDGE_MARGIN`, `TEXT_MARGIN`, and the `TECH_LABEL` map for
  access-technology names
- `phone-gestures`: `SCREEN_W/H`, `KEYBOARD_TOP` (px), the drag→line and
  tap sensitivities, and `UID`/`TMUX`/`SESSION` for the tmux socket
- `sms-send`: `SMSC` in `/etc/phone-sms.conf` (template:
  `telephony/phone-sms.conf`, installed only when none exists) — the
  message center, operator/SIM-specific; find yours from the SIM's
  EF_SMSP record or the operator's docs (this modem sends nothing
  without it). The polkit rule (`49-modem-voice.rules.in`) has an
  `@USER@` placeholder that `install-telephony.sh` fills in with the
  device user, so no edit is needed.
- `sms-handler`: `COMMAND` in `/etc/phone-sms-handler.conf` (template:
  `telephony/phone-sms-handler.conf`, installed only when none exists) —
  what to do with each received SMS, with the forwarding example inside
- `call-watcher`: `RING_WAV`, the ring `--volume=` (0–65536 linear), and
  the state/mute flag paths (shared with `phone-volume` and
  `phone-statusbar`)
- `notify-led`: `LED` (sysfs brightness path) and `PATTERNS` (the blink
  timings) — and the udev rule's `KERNEL=="white:indicator"` match if
  your LED is named differently
- Colors are RGB tuples near the top of `phone-statusbar`

Nothing names the device user: the installers and the graphical scripts
(`app`, `app-inner`, `swaybar-user`, `phone-screenshot`) resolve the
user at run time as the owner of the single home under `/home` — by uid,
so any username works. The one exception is `phone-gestures`' `UID`
constant (uid 10000, the postmarketOS default).

**Battery tunables** live in `/etc/phone-statusbar.conf` (template:
`statusbar/phone-statusbar.conf` in this repo) — no code edits needed, and a
restart applies them (`doas systemctl restart phone-statusbar`):

- `MODEM_EVERY` (default 300 s) — how long the mmcli result is cached.
  Every fetch is a D-Bus round-trip that wakes ModemManager, so raising
  this is the single biggest saver: 300 s = 288 queries/day, 900 s = 96.

It trades freshness for battery — see the comments in the file. While
the screen is dark the daemon doesn't poll at all: the backlight has a
single writer (`phone-screen-toggle`) which SIGUSR1s it on wake.

**Backlight tunables** live in `/etc/phone-brightness.conf` (template:
`brightness/phone-brightness.conf`): `MIN_BRIGHTNESS` (dark-room level),
`MAX_BRIGHTNESS`, `LUX_MAX` (ambient light that maps to the max), and
`POLL_EVERY` (sample interval while lit — raising it saves battery at
the cost of reacting slower when you move between rooms).

**IR codes** live in `/etc/phone-ir/remotes.conf` (template:
`ir/phone-ir-remotes.conf`): `NAME = nec 0x04 0x08`, `samsung`, `sirc`, `rc5`,
`necext`, `raw CARRIER DUTY MARK SPACE ...` or `ref OTHER_NAME`. A name on
several lines sends all of them in turn, 150 ms apart (`GAP_S` in
`phone-ir`). The format is documented in the template.

**Framebuffer gotcha:** read `stride` from
`/sys/class/graphics/fb0/stride` and trust it over `width * 4` — this
device reports 1080×2280 @ 32bpp but a stride of **4352**, not 4320
(32-byte row padding). If your bar comes out diagonal or smeared, this is
why. The pixel format assumed is BGRx little-endian, which matches the
common `FB_VISUAL_TRUECOLOR` + 32bpp case.

If your device has no notch, shrink `BAR_H` to `2 × font_height` of
whatever the smallest console font you use is, so the bar never eats more
than two terminal rows.
